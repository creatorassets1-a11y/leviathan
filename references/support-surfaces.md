# Support & Trust Surfaces

Support is part of the product, not an afterthought. For non-trivial user-facing products, Leviathan requires a coherent path from first use to self-service help, recovery, contact, and escalation.

## Required surfaces

### Help / FAQ / Knowledge Base

Provide a searchable and categorized help surface based on the actual product. Cover onboarding, core workflows, billing and cancellation where applicable, privacy/data controls, permissions, common failures, account recovery, and troubleshooting.

Every article must use the actual UI labels and behavior. Do not invent capabilities, response times, limits, pricing, or support guarantees.

### Product Guide / Walkthrough

Explain the first useful task and each major workflow in sequential, end-user language. Include common edge cases and recovery paths. Link from onboarding, meaningful empty states, and Help.

### Contact / Support

Provide a reachable support channel appropriate to the product. State what the channel supports and any response expectation only when that expectation is actually operational. Privacy, legal, accessibility, and security requests should have a clear route when applicable.

If ticketing is used, retain a request identifier, status, timestamps, and relevant history. Never expose internal notes or secrets to the requester.

### First-run and recovery

The first-run experience should explain the product's primary value and provide a useful next action. Support content must cover session expiry, account recovery, payment failures, permission problems, and other predictable blockers.

## Content contract

Support copy must:

- describe actual behavior;
- use specific product vocabulary;
- avoid generic AI-generated filler;
- give a concrete next action;
- link directly to the relevant setting, feature, or policy where possible;
- be accessible and usable on mobile;
- have an owner or maintenance mechanism.

## Verification

Evidence should demonstrate:

- Help is reachable from the product;
- core questions have answers;
- guide links resolve and match the current UI;
- contact requests can actually be submitted or the limitation is recorded;
- privacy/legal/security routes work where promised;
- empty/error states point users toward useful support when appropriate.
