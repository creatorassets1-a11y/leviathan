# Changelog & Release Communication

## Purpose
Material product changes should be understandable to users, operators, and support staff.

## Requirements
- Maintain a versioned changelog or equivalent release record for user-visible changes.
- Classify changes as new, improved, fixed, changed, deprecated, or security-related as useful.
- Security/privacy incidents use the incident process rather than relying on a public changelog alone.
- Communicate material billing, entitlement, privacy, Terms, data-use, or breaking changes through the appropriate product/email/legal channels with required notice periods.
- Never expose internal secrets, vulnerability details that enable exploitation, private customer data, or unverified claims.
- Link release notes to updated Help/Guide content when behavior changes.
- Support/admin teams receive internal notes for operationally relevant changes.

## Evidence
- release artifact exists for user-visible releases;
- material policy/billing changes have corresponding user communication;
- changed Help/Guide pages match the release;
- deprecation notices include migration/replacement guidance where needed;
- release provenance/version is linked to deployment identity.
